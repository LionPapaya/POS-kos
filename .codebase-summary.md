# POS-kOS Codebase Summary

**Project**: Poseidon SSTO Operating System (POS-kOS)  
**Language**: KSP's KOS scripting language  
**Purpose**: Autonomous flight control system for Poseidon SSTO spacecraft in Kerbal Space Program  
**Target Game**: KSP 1.12.5 with KOS mod, Ferram Aerospace Research (FAR), and Giulio Dondi's FAR fork

---

## Project Overview

POS-kOS is a complete automation system for the Poseidon SSTO (Single-Stage-to-Orbit) spacecraft. It handles three major flight phases:
1. **Launch**: Automated ascent with adaptive pitch control, engine mode switching, and circularization
2. **Orbital Maneuvering**: Orbital transfers, rendezvous, and orbital adjustments
3. **Reentry**: Autonomous deorbit, atmospheric entry, and runway landing

**Key Constraint**: Scripts are exclusively designed for the Poseidon SSTO and rely heavily on its specific aerodynamic properties, and engine configuration.

---

## Architecture Overview

### Entry Points & Flight Phase Routing

**Primary Entry**: `Script/POS.ks` - Main state machine that routes to flight phases
- Initializes all libraries and GUI
- Detects current flight state (atmosphere/orbit/altitude)
- Routes to appropriate mode:
  - `POS1` → `Poseidon_SSTO_Orbit_Main.ks` (launch/orbit operations)
  - `POS3` → `Poseidon_SSTO_Reentry.ks` (reentry/landing)
  - `OM1` → `Poseidon_SSTO_OM1.ks` (orbital maneuvering)
  - `POS2` → `Poseidon_SSTO_Docking.ks` (docking operations)

**GUI System**: `create_main_gui()` provides interactive control panel for selecting mission phases.

### Core Flight Phases

#### 1. Launch (`Poseidon_SSTO_Orbit_Main.ks`)
- **Sequence**: Launch → Ascent → Circularization → Orbit
- **Key Variables**: `TargetPeriapsis`, `TargetApoapsis`, `TargetInclination`
- **Control**: Adaptive pitch guidance based on altitude/airspeed
- **Engine Management**:
  - RAPIER engines in "AIR" mode below 30km
  - Switches to closed-cycle mode at altitude
  - NERV activation once above 70km periapsis
- **Special Logic**: Validates orbit parameters, prevents invalid inputs

#### 2. Reentry (`Poseidon_SSTO_Reentry.ks`) - 736 lines
- **Sequence**: Deorbit calculation → Atmospheric entry → Guided descent → Runway landing
- **Modes**: `reentry_low`, `reentry_mid`, `reentry_high`, `reentry_int`
- **Special Features**:
  - Closed-loop reentry algorithm
  - Automatic runway selection
  - Bank angle control for guidance during descent
  - Lift-to-drag ratio calculation using FAR aerodynamic forces
  - Mach number monitoring with FAR addon

#### 3. Orbital Maneuvering (`Poseidon_SSTO_OM1.ks`)
- Integrates with RSVP library for transfer calculations
- Supports vessel-to-vessel, vessel-to-body, body-to-body transfers

## Core Libraries

### RSVP (Rendezvous & Surface Planning)
**Location**: `Script/Libraries/rsvp/`

Central orbital mechanics library with modular design:
- **main.ks**: Entry point, exports `goto()` function
- **lambert.ks**: Solves Lambert's problem (transfer orbit calculation)
- **transfer.ks**: Calculates maneuver requirements between vessels/bodies
- **maneuver.ks**: Creates and manages maneuver nodes
- **orbit.ks**: Orbital element calculations and state vector operations
- **search.ks**: Search algorithms for launch windows
- **refine.ks**: Optimization and refinement of transfer solutions
- **hill_climb.ks**: Hill climbing algorithm for delta-v optimization
- **validate.ks**: Parameter validation and error checking

**Key Interface**:
```
rsvp:goto(destination, options) 
  → Returns {success, transfer, result, details}
```

### Steering & Control

**lib_aerostr.ks**: Atmospheric steering
- Manages aerodynamic-based attitude control
- Target pitch, roll, heading angles
- Bank control for atmospheric flight

**lib_vacstr.ks**: Vacuum steering
- Reaction Control System (RCS) attitude control
- Vacuum flight dynamics
- No atmospheric drag effects

**control.ks**: Digital Autopilot (DAP)
- Global `dap` lexicon manages all flight control
- **Components**:
  - `dap["aerostr"]`: Aerodynamic steering state
  - `dap["aoa"]`: Angle-of-attack and bank angle control
  - `dap["css"]`: Control surface smoothing/damping rates
  - `dap["str_mode"]`: Steering mode selector (aerostr/vacstr)
  - `dap_steering`: Main steering output (heading/pitch/roll)
  - `dap:update()`: Called every frame for control updates
  - `dapthrottle`: Throttle output (0-1 range)

**Navigation**: 
- `lib_navigation.ks`: Spherical geometry calculations
  - `get_geoposition_along_heading()`: Geolocation prediction using bearing/distance
  - `calcdistance()`: Great-circle distance using Haversine formula
  - `get_geoposition_on_circle()`: Circular path calculations

### Utilities

**lib_math.ks** (476 lines): Mathematical functions
- `time_to_alt()`: ETA to target altitude given vertical velocity
- `time_to_pos()`: ETA to target position given ground speed
- `str_to_num()`: String-to-number conversion with scientific notation support
- `changeRate()`: Smooth value transitions
- `lerp()`: Linear interpolation
- `remove_spaces()`: String processing

**lib_navball.ks**: Navball and reference frame management

**lib_input_terminal.ks**: Terminal UI for user interaction and parameter input

**lib_location_constants.ks**: Hardcoded runway/landing site coordinates and properties

**lib_aerosim.ks**: Aerodynamic simulation and force calculations

### Craft Definition

**craft_Poseidon_SSTO.ks**:
- `reset_sys()`: System initialization based on current flight state
  - Activates/deactivates engines, gear, brakes, lights based on altitude
  - Configures RCS, SAS, and reaction wheels
- `check_inputs()`: Validates user-entered orbit parameters
- `goto_target()`: Target position management for landing

**Hardcoded Craft Properties**: References to specific engine types, fuel tank configurations, and mass properties specific to Poseidon SSTO

## Data Flow & Control Cycle

```
POS.ks (Main Loop, 50ms cycle)
  ├─ Detects flight state (atmosphere/orbit/altitude)
  ├─ Routes to appropriate phase
  └─ Each phase runs until completion
    ├─ Poseidon_SSTO_Orbit_Main.ks
    │  ├─ Calls dap:update() for attitude control
    │  ├─ Updates steering angles based on guidance algorithm
    │  ├─ Manages engine throttle and mode switching
    │  └─ Monitors ascent progress
    └─ Poseidon_SSTO_Reentry.ks
       ├─ Calculates deorbit maneuver
       ├─ Calls dap:update() with aerodynamic steering
       ├─ Adjusts bank angle for guidance
       └─ Manages descent to runway
```

### Global State Variables
- `main_step`: Current flight phase ("findstep", "ask_Step", "POS1", "POS3", "OM1", "POS2")
- `dap`: Flight control system state (steering, throttle, modes)
- `nervs`: NERV engine activation flag
- `rapier_mode`: RAPIER engine mode ("air" or "closed")
- `rapiers`: RAPIER engine status
- `TargetPeriapsis`, `TargetApoapsis`, `TargetInclination`: User-specified orbit parameters

## Key Patterns & Conventions

### 1. Library Initialization
All scripts use `RUNONCEPATH()` for one-time library loading:
```
RUNONCEPATH("0:/Libraries/lib_name.ks").
```
This prevents code duplication while allowing modular organization.

### 2. Lexicon-Based State Management
Global state stored in dictionaries (lexicons):
```
global dap is lex().
dap:add("key", value).
```
Advantages: Namespace isolation, dynamic property access, organized state grouping

### 3. Steering Architecture
- **Outer loop**: Calculate desired pitch/heading/roll (guidance)
- **Middle loop**: Smooth control transitions via `dap["css"]` damping
- **Inner loop**: KOS steering manager handles control surface mapping
- **Mode switching**: Toggle between `aerostr` (atmospheric) and `vacstr` (vacuum)

### 4. Flight Phase Sequencing
Each phase script manages substeps via a `step` variable:
```
if step = "Launch"
  → if altitude < 85m → ignite engines
  → if altitude > X → adjust pitch
  → if apoapsis > target → cut engines
  → set step to next phase
```

### 5. Altitude-Based Operational Decisions
Many functions branch on altitude thresholds:
- `altitude < 50000m` → Atmosphere (use RAPIER engines)
- `altitude > 70000m` → Vacuum operations (use NERV engines)
- `altitude < 10m` → Landing phase

### 6. FAR Aerodynamic Integration
Uses `ADDONS:FAR` for aerodynamic calculations:
- `ADDONS:FAR:mach` - Current Mach number
- `ADDONS:FAR:AEROFORCE` - Aerodynamic force vector
- `cur_aeroforce_ld()` - Lift/drag ratio calculation

## Important Implementation Details

### Engine Management
- **RAPIER engines** (air-breathing):
  - Function: `rapierson()`, `rapiersoff()`, `togglerapiermode()`
  - Used during ascent up to ~30km altitude
  - Must be switched to closed-cycle mode at altitude
  
- **NERV engines** (nuclear, vacuum only):
  - Function: `nervson()`, `nervsoff()`
  - Activated once periapsis > 70km
  - Provides high specific impulse for orbital operations

### Reentry Strategy
1. Calculate deorbit burn based on current apoapsis
2. Execute burn to lower periapsis below atmosphere
3. Route to appropriate reentry mode based on apoapsis:
   - `reentry_low`: < 500km apoapsis
   - `reentry_mid`: 500-1000km apoapsis
   - `reentry_high`: 1000-10000km apoapsis
   - `reentry_int`: Interplanetary or very high orbits
4. Manage bank angle during descent for lateral guidance
5. Navigate to runway target using guided descent algorithm

### RSVP Integration Pattern
```
1. rsvp:validate_parameters() - Check inputs
2. rsvp:find_launch_window() - Calculate transfer
3. rsvp:vessel_to_vessel/body_to_body/etc() - Create maneuver nodes
4. Monitor maneuver execution from main script
```

## Known Limitations

1. **Interplanetary Reentry**: Reentry from interplanetary altitudes (>10M km) not yet fully implemented
2. **Craft-Exclusive**: All systems tuned for Poseidon SSTO; won't work with other craft
3. **Runway-Dependent**: Landing system requires predefined runway coordinates
4. **FAR Dependency**: Full reentry guidance requires Ferram Aerospace Research mod

## Development Workflow

### Adding a New Feature
1. Create function in appropriate library (lib_*.ks or rsvp/*.ks)
2. Load library via `RUNONCEPATH()` in phase scripts
3. Call function from flight phase script (e.g., Poseidon_SSTO_Orbit_Main.ks)
4. Test in-game with appropriate flight conditions

### Debugging Approach
- Log output to `0:/log.txt` using: `log "message" to "0:/log.txt".`
- Check console output during flight via KOS terminal
- Readouts updated via `update_readouts()` for GUI display
- Use `print` statements for quick debugging (visible in terminal)

### Critical Variables to Monitor
- `ship:altitude` - Current altitude
- `ship:periapsis`, `ship:apoapsis` - Current orbit
- `ship:airspeed` - Current speed
- `dap["aerostr"]["targetPitch"]` - Guidance pitch command
- `dapthrottle` - Engine throttle command

## Quick Reference: Common Tasks

### To Launch the Spacecraft
1. User selects "Launch" from GUI in POS.ks
2. `main_step` → "POS1" → Loads Poseidon_SSTO_Orbit_Main.ks
3. Script initializes DAP, sets `step` to "Launch"
4. Automatic ascent with adaptive pitch guidance
5. Circularizes to user-specified orbit
6. Returns to GUI for next operation

### To Execute an Orbital Maneuver
1. Select "Maneuver" from GUI
2. `main_step` → "OM1" → Loads Poseidon_SSTO_OM1.ks
3. RSVP library calculates transfer
4. Maneuver nodes created automatically
5. Execution monitored and guided

### To Perform Reentry
1. Select "Reentry" from GUI or auto-trigger at atmosphere boundary
2. `main_step` → "POS3" → Loads Poseidon_SSTO_Reentry.ks
3. Calculates deorbit burn (if needed)
4. Routes to appropriate reentry mode based on apoapsis
5. Manages atmospheric descent with bank angle guidance
6. Lands on runway with automatic touchdown
